# استكشاف الأخطاء

## الحالة العامة

إذا ظهر خطأ أثناء التشغيل، فغالبًا السبب يكون في أحد الأمور التالية:
- متغيرات بيئة غير صحيحة
- ملف `DATABASE_URL` منتهي بشكل غير صحيح
- تبعيات غير مثبتة
- صورة/ملف ثابت مفقود
- خدمة خارجية غير مهيأة

## 1) خطأ في قاعدة البيانات أو DSN

### الأعراض

- رسالة تحذير حول DSN أو connection string
- التطبيق يبدأ لكنه لا يقرأ البيانات كما ينبغي
- استثناءات عند الوصول إلى الصفحة الرئيسية أو القرارات

### الحل

1. تأكد من صحة قيمة `DATABASE_URL`
2. إذا كنت تعمل محليًا، استخدم SQLite بشكل افتراضي
3. إذا كنت تحتاج PostgreSQL، تأكد من أن URL يتبع الصيغة الصحيحة

```env
DATABASE_URL=postgresql://user:password@host:5432/dbname
```

## 2) الصفحة لا تفتح

### تحقق من

```bash
python run.py
```

ثم افتح:

```text
http://localhost:5000
```

إذا لم يفتح، تحقق من:
- أن المشروع يشتغل في البيئة الصحيحة
- أن جميع الحزم تم تثبيتها
- عدم وجود خلل في الملف `run.py`

## 3) ملف ثابت مفقود

### الأعراض

- واجهة غير مكتملة
- صور أو أنماط CSS غير موجودة
- أخطاء في المتصفح على ملفات JS/CSS

### الحل

- تأكد من وجود مجلد `static/`
- تأكد من أن الطرق الموجودة في القوالب تشير إلى ملفات موجودة فعليًا
- التحقق من اسم الملف واللاحقة بدقة

## 4) أخطاء import أو تبعيات

### الحل

```bash
pip install -r requirements.txt
```

وإذا كان المشروع يحتاج أدوات التطوير:

```bash
pip install -r requirements-dev.txt
```

## 5) فشل الاختبارات

### الحل

```bash
python -m pytest tests -q
```

إذا فشل جزء محدد، اقرأ تفاصيل الخطأ ثم تابع التحقق من:
- القيم في fixtures
- حقول البيانات المطلوبة
- حالة قاعدة البيانات في الاختبار
- التوابع الخارجية التي تم محاكاتها باستخدام mock

## 6) التحقق السريع

```bash
curl http://localhost:5000/api/health
```

إذا عاد response صحيحة، فهذا يشير إلى أن التطبيق يعمل بشكل أساسي.

## 7) عند الحاجة إلى الدعم

قبل طلب المساعدة، جمع هذه المعلومات:
- نسخة Python
- نوع قاعدة البيانات المستخدمة
- قيم `DATABASE_URL` (بدون كلمة المرور الحقيقية)
- آخر رسالة خطأ كاملة
- خطوة تكرار المشكلة
